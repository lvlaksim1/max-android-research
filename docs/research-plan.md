# План исследования

## Этап 1 — фиксация образца
- SHA-256 исследуемого APK и версия приложения.
- Воспроизводимый перечень файлов, проверка целостности ZIP.
- Статические сведения о манифесте, разрешениях, компонентах и библиотечных зависимостях.

## Этап 2 — архитектура
- Классы и точки входа авторизации.
- Клиенты запросов, структура DEX и нативных библиотек.
- Локальное хранилище, уведомления, работа в фоне.
- Отделение статически наблюдаемых фактов от предположений.

## Этап 3 — динамическая проверка (при наличии записи)
- Поведение при запуске, авторизации и обмене сообщениями.
- Сопоставление запросов с участками кода.
- Проверка сетевых адресов, последовательностей и форматов без угадывания.

## Правила
- Исходный APK и входящие материалы не изменять.
- Исходные сведения, проверенные факты и гипотезы учитывать раздельно.
- Не публиковать личные данные, секреты, токены или содержимое переписок.
- В Git только компактные текстовые материалы; тяжёлые двоичные файлы не добавлять.
- Исследовательские результаты проверять локально; не утверждать, что признаки из DEX автоматически означают реальное поведение.
