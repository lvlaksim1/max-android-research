## Инструментирование

В `tools/patch_mobileid_diagnostics.py` внедрена запись **только обезличенных событий**:
- `one.me.android.OneMeApplication.onCreate` — инициализирует ссылку на контекст приложения;
- `dol.a` — `bridge_request` при обращении к делегату WebAppVerifyMobileId;
- `fcl.a` — `cellular_http_attempt` перед сетевой операцией.

Каждое событие сохраняется в файл приложения `/sdcard/Android/data/ru.oneme.app/files/mobileid-research.jsonl` в виде `{"schema":1,"time_ms":...,"event":"..."}`.

Для получения журнала с тестового устройства по USB с Android Platform Tools:
```powershell
adb pull "/sdcard/Android/data/ru.oneme.app/files/mobileid-research.jsonl" "."
```

Не записываются номера аккаунтов и SIM, данные подписанной WebAppData, куки, токены, секреты сеанса, URL проверки Mobile ID, HTTP-заголовки, тело ответа и коды подтверждения. Результат предназначен для измерения порядка этапов, а не для восстановления доверенного сеанса на ПК.

## Техническая граница задачи

Пользовательская цель — экспорт тестового авторизационного состояния с телефона и перенос в MAX Desktop. Этот файл и данная модификация **не выполняют перенос авторизационных данных**. Пересадка действительных сессионных ключей и операторских подтверждений не реализуется, поскольку позволила бы воспроизвести доверенный сеанс вне подтверждённого устройства. Допустим перенос только обезличенных диагностических данных и стандартных настроек.

Репозиторий MAX Desktop и системный VPN не изменялись. Последняя опубликованная версия MAX Desktop v0.1.21.
